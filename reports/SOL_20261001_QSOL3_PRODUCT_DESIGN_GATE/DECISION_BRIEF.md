# StudyGrid design gate — decision brief

General CF-0047 · Sol CF-0043 · Q-SOL3 · Design only

**Recommend a context workspace with a guided study session inside it. No implementation release.**

| Complete alternative | Organising object | Strength | Material tradeoff |
|---|---|---|---|
| A — Context workspace | Class or personal collection | Clear place/role; easy class switching; closest to current route/state model | Home must earn its place and Study/Materials/Progress need distinct jobs |
| B — Guided work queue | Task or learning plan | Strongest chronology and one-next-action clarity | Needs real plans/recommendation evidence; less direct course exploration/class switching |
| C — Material library/canvas | Source material/topic | Strong reading/provenance and personal-study symmetry | Risks a large rail again and practice as an afterthought; responsive pane complexity |

Choose A's Home→context→Study/Materials/Progress hierarchy. Use B's bounded teach→retrieve→optional confidence→feedback/error review→completion journey within Study, and C's optional source drawer. No additional cross-context planner, second library navigation system or mandatory split screen.

The proposed app keeps one Home/workspace/account header and one class/personal context strip. Instructor context is explicit `Teach`; learner preview is read-only, labelled, and returns to its origin. Personal study uses the same content/study model without a formal class. Collapse Quick/Focused/Deep unless distinct content plans/outcomes are demonstrated; Continue learning leads, exploration remains secondary.

Browser Back follows meaningful history; named Up goes to the semantic parent; Home opens the current workspace root; Sign out is explicit account exit. Task answers/approvals are state updates, not history entries or replayable actions. Public/onboarding is outside signed-in hierarchy, with truthful local-preview boundaries. Actual auth integration is outside this gate.

Keep the15-item review and Approve & next in a persistent dock. Every final decision reaches an explicit summary, with approved/held/changes counts. Ready depends on actual current-revision approvals; publication remains separate and Published requires a supported receipt. Existing local publication is preview only.

Use a fixed-stage ordered shared-axis welcome loop, continuous1→2→3→1 while idle, readable rest, explicit Pause/Play, engagement pause, static semantic3-step equivalent and static/manual reduced motion. Numbering carries sequence without motion. Timings are prototype hypotheses; the rotor and quiet crossfade remain alternatives.

The assessment foundation separates domain content from interaction, scoring, feedback policy, evidence and accessibility. Minimum types: single, unordered multi, sequence, matching, categorisation and constructed response. Ordering uses inspectable numbered rows with Move up/down and position choice; drag is optional. Keyboard and single-pointer paths require separate testing. The existing q4m is **not converted**: its cited PFP207 guide must establish whether order is required. Owner's native multi-select failure stays open despite isolated callback success.

All SOL-F01…F06 and pool divergence have dispositions. Preserve source terms, version-bound attempts/reviews, optional-confidence/null behaviour, actual reviewed-section state, reward idempotence/rollback, fixed tour disclosure and privacy/example truth. Automatic Seeds follow eligible completion, with honest save failure; reading flags never mean mastery.

**Selection required through General:** main model/synthesis; session taxonomy and role/navigation consolidation; welcome treatment/exact visual placement; bounded prototype scope before later implementation release. Already directed owner requirements are constraints, not preferences to re-ask.

**Evidence dependencies:** primary q4m course source/pool membership; exact rendered/native failure states; target/focus geometry and iPad/Safari/VoiceOver QA; truthful save/publication capability. These do not prevent delivering the conceptual package.
