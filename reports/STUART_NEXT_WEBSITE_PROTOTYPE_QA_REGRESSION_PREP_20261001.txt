A. TONIGHT MUST-PASS GATE — ALL REQUIRED FOR PASS
======================================================================

G01 EXACT IDENTITY
Candidate filename, version, Drive/storage pointer, byte size and SHA-256 are supplied and independently verified. Candidate must be a new non-canonical artifact built from the exact accepted baseline above.
FAIL: source identity uncertain, hash mismatch, overwritten accepted base, or candidate bytes not retrievable.

G02 PARSE / STARTUP HEALTH
All executable inline JS parses; page renders without pageerror/console error on first load and representative routes.
FAIL: parse/runtime exception affecting product flow.

G03 SIGNED-IN ROOT / BACK CONTINUITY
Signed-in root is Home/current workspace. Back from signed-in product pages must not walk into onboarding/public flow. Empty Your Classes dead-end is removed/merged into a useful Home/current-workspace model.
FAIL: signed-in root still acts as onboarding/class-setup root or Back exposes public/start flow unexpectedly.

G04 HOME / INSTRUCTOR NAMING + ROLE CONTEXT
Professor Home is Home. Instructor, instructor-preview, learner-personal-study and class context are explicit at transitions.
FAIL: user can reasonably lose whether they are instructor, previewing, or studying personally.

G05 CLASS SWITCHING / ORIENTATION
Switching class is easy and does not duplicate course identity/chrome excessively. Selected class remains explicit after switch.
FAIL: wrong class content, ambiguous class, lost role/context, or stale class action.

G06 ONE STRONG NEXT ACTION
Continue / Up next is visually primary, gives a short honest reason, and offers an escape/secondary route where appropriate. It must read as a recommendation, not mastery truth.
FAIL: multiple equal primaries, unsupported mastery wording, no reason, or no appropriate escape.

G07 STABLE SAME-LEVEL STUDY SHELL
Learn/Test/Support (or equivalent same-level modes) preserve primary shell anchors. Main same-level targets do not jump materially between modes.
PASS evidence: bounding-box delta for the mode row / primary target <= 2 px in x/y unless a documented responsive breakpoint intentionally changes layout.
FAIL: moving primary targets comparable to accepted-baseline Test shift.

G08 KEYBOARD FOCUS
All new/changed controls are keyboard reachable with visible, consistent on-brand focus. No keyboard trap.
FAIL: missing focus, hidden focus, unreachable control, or focus artifact obscuring content.

G09 DIALOG / POPOVER ESCAPE + RETURN FOCUS
Escape closes applicable overlays and returns focus to the invoking control. Explicit close does the same.
FAIL: focus loss to body/top-of-page, trapped overlay, or closed overlay retaining focus.

G10 REDUCED MOTION
Welcome/rotor and any new transition respect prefers-reduced-motion. Meaning and manual controls remain available without autoplay-dependent comprehension.
FAIL: essential information depends on motion; reduced-motion still auto-animates materially; controls disappear.

G11 MULTI_SELECT_UNORDERED
True unordered multi-select allows required selections in any order; correctness is set-based; order does not affect score; minimum/maximum/required count is clear.
FAIL: [A,B,C] correct but [C,A,B] wrong; checkbox order treated as sequence; accidental single-select fallback.

G12 SEQUENCE_ORDER + NON-DRAG ALTERNATIVE
Ordered constructs use visible numbered order and actual order-sensitive scoring. Drag is optional; Move up/down or Choose position (keyboard/single-pointer usable) is available.
FAIL: ordered construct represented as ordinary checkboxes; drag-only operation; incorrect order accepted as correct.

G13 ANSWER FEEDBACK SEMANTICS
After answer: clearly separate what happened, what to learn, what next. Confidence remains optional self-report and cannot visually/semantically become competence.
FAIL: dense metadata dump; answer-exposed repeat treated as fresh competence; confidence drives success/mastery wording.

G14 INVALID/BROKEN ITEM OR SCORER
Broken content/interaction/scorer state surfaces neutral technical/content-review state and does not record learner failure.
FAIL: software/content failure shown as wrong answer or competence decrease.

G15 LOW-STAKES HELP / REMEDIATION
Explicit help is available when policy permits. Unsolicited help is non-shaming, bounded per episode, and does not loop indefinitely.
FAIL: repeated nagging, trait labels, forced remediation, or help request interpreted as weakness evidence.

G16 PROTECTED ASSESSMENT SHIELD + ACCESSIBILITY
Protected assessment suppresses coaching/reveal according to policy, including stale/cached practice help. Authorized accessibility/accommodation support remains independently available.
FAIL: answer/explanation leak; generic assistance switch disables valid accessibility; learner override bypasses assessment rules.

G17 AGENCY WITHOUT COMPETENCE INFERENCE
Skip/dismiss/choose another/help/pause/continue may alter the next decision only. It must not directly change mastery, weakness, motivation or engagement presentation.
FAIL: override/help/dismiss changes competence/progress label by itself.

G18 STUDY SET APPROVE-AND-NEXT TARGET STABILITY
Across the 15-question review queue, Approve and next stays physically stable enough for repeated review.
PASS evidence: button x/y delta <= 2 px for same viewport after initial canvas settles, or equivalent fixed action bar whose target remains stable.
FAIL: target jumps with question text/rationale height.

G19 STUDY SET FINAL ITEM COMPLETION
Approving final required item transitions to explicit finalization/completion state; it must not cycle back to an already-approved question as though review is unfinished.
FAIL: Approve and next remains active with no clear completed/finalized state after 15/15.

G20 STUDY SET STATE TRUTH
Draft / Ready / Published / Held / All correspond to real local prototype state changes and filters, not decorative labels.
FAIL: label disagrees with question review state or publication/hold status.

G21 REWARD / SEED TRUTHFULNESS
Reward/seeds auto-collect only on a successfully committed qualifying action. Failure/disconnected save cannot render success/reward.
FAIL: reward appears after failed/aborted action or preview/demo creates learner reward.

G22 RETRY / DOUBLE-SUBMIT / DUPLICATE RECOMMENDATION UI PATHS
Rapid double click, retry and obvious re-entry do not create two visible attempts/evidence units/rewards/recommendations for one logical action.
FAIL: duplicate visible history, duplicated progress, doubled reward, or two accepted next actions from one semantic action.

G23 DESKTOP / TABLET / PHONE SMOKE
Representative signed-in Home, class overview, Learn/Test/Support, instructor Home/class Study Set, settings and completion surfaces render without horizontal overflow or inaccessible primary controls at 1024x900, 820x900 and 390x844.
FAIL: clipped/offscreen primary action, horizontal page overflow, or route crash.

G24 UNCHANGED ACCEPTED FLOWS
Outside the bounded revision, previously accepted welcome accessibility, current routes, feedback/help shell and representative instructor/course flows remain functional.
FAIL: unrelated regression in accepted flow.

G25 OWNER-VISIBLE EXACT HTML DELIVERY
Exact verified candidate bytes are published through a chat-accessible owner artifact path. Delivery byte identity must match tested candidate SHA/size.
FAIL: only a mounted/container path or Drive ID is offered, delivered bytes differ, or tested candidate identity cannot be tied to owner artifact.

PASS / AMEND / BLOCKED RULE
PASS: all G01-G25 pass on exact candidate bytes; no material broader regression blocker.
AMEND: exact candidate is verifiable/runnable but one or more must-pass behaviours or material broader regressions fail with a bounded repair path.
BLOCKED: exact candidate/source identity cannot be verified/retrieved; candidate cannot run sufficiently to test; or a critical assessment-integrity / destructive-state / owner-delivery verification boundary prevents a defensible verdict.
