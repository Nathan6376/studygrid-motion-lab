4. P1 DEFECTS — INDEPENDENTLY CORROBORATED
======================================================================

ST-P1-01 — DRAFT SOURCE CAN STILL REACH A LEARNER
Classification: P1 / code defect + missing negative test
Corroborates: Sol F1

Independent source reproduction:
- provider envelope correctly computes approvedSourceIds.
- provider isReleased() checks module release + lesson presence but does not require the topic/task source to remain approved.
- NEW/REVIEW/READY/APPLY planning relies on those topic/task paths without a current source-approval gate.
- learner SourceSheet resolves the source directly and renders its excerpt regardless of Draft/Approved status; when Draft it literally shows “Draft, not shown to students” while showing the excerpt.
- the learner can also mark that draft source Reviewed because the Reviewed toggle is rendered for non-Teaching contexts.

Concrete fixture: src-bio-osmosis is an approved Biology source cited by the Osmosis task family. Returning it to Draft in Teaching removes it from Materials, but does not make those task/session/source paths ineligible.

Master conflict: School students see only approved material.

Minimum acceptance repair:
- one current learner-delivery eligibility policy must require approved source identity for learner question/session/source/debrief access;
- returning source to Draft blocks new delivery and blocks learner Show source on that content;
- historical attempt receipts remain historical rather than being rewritten;
- reapproval restores only intended eligible content.

ST-P1-02 — PAUSED SESSION BYPASSES CURRENT RELEASE / CHECKPOINT / SHARE ELIGIBILITY
Classification: P1 / code defect + missing negative tests
Corroborates: Sol F2

Independent source reproduction:
- VisitStore.start() sees an existing unfinished session and directly marks it active; it does not ask provider.plan() whether the session is still allowed.
- an existing completed session is also returned directly.
- setReleased(), setSourceStatus(), setCheckpointConfirmed() and shareStudySet() update Teaching state without advancing an eligibility/envelope generation or invalidating affected session generations.
- provider.recommend() returns paused work before revalidating the paused session against the current envelope.
- submit/help/completion have no current-release-envelope check.

Therefore a paused NEW session can survive module/source withdrawal, READY can survive checkpoint unconfirmation, and a shared-set session can survive withdrawal of sharing.

Minimum acceptance repair:
- current eligibility must be checked on recommend/resume and before evidence-affecting submit/help/completion;
- a Teaching eligibility change must invalidate or version affected in-flight work;
- reopening is explicit and recoverable, not silent reauthorisation;
- historical local receipts remain visible as history.

ST-P1-03 — “SAY IT ANOTHER WAY” HELP CAN STILL PRODUCE CLEAN / “ON YOUR OWN” EVIDENCE
Classification: P1 / evidence-truth code defect + missing test
Corroborates: Sol F3

Independent source reproduction:
- Stuck? → Say it another way calls store.help(..., 'another-way').
- the UI explicitly says “Noted as extra help for this question.”
- store passes support.anotherWay into AttemptSubmission.
- provider.submit() decides helped using attempt>1, hint, revealed, priorMisses and previouslySeen — but omits support.anotherWay.
- a first-try correct response can therefore be evidence='clean'.
- TaskCard then renders “Right first time, on your own.” and completion/progress can count that clean evidence.

Minimum acceptance repair:
- another-way displayed before committed answer must count as substantive help/exposure;
- first correct answer after it must not produce clean/on-your-own evidence;
- completion/progress/debrief must inherit the corrected evidence status.

ST-P1-04 — RESTART CAN LAUNDER UNANSWERED HELP/EXPOSURE BACK INTO “UNSEEN/FRESH”
Classification: P1 / evidence-lifecycle code defect + missing interruption test
Corroborates: Sol F4

Independent source reproduction:
- seenTaskIds/freshAvailable are derived from submitted global receipts only.
- help/exposure before any submission lives in the current TaskRun.
- restart() deletes the session and recreates it from global receipts.
- if another-way help was shown before the first submission, no receipt records that presentation/exposure.
- the recreated run can therefore mark the same task previouslySeen=false and fresh eligibility can include it again.

This violates the contract requirement that fresh re-check be a different/unexposed or parallel item; explicit Reset practice is the action that should clear visit history, not ordinary restart.

Minimum acceptance repair:
- record actual presented/helped item exposure separately from submitted attempt receipts;
- preserve it across restart/pause/resume within the visit;
- do not mark undisplayed queued items exposed merely because they existed in a plan;
- fresh independent evidence requires a distinct eligible unexposed parallel item.

ST-P1-05 — COMPLETED SESSION REUSE BREAKS “START / FRESH REVIEW / PLAY AGAIN” PROMISES
Classification: P1 / session-instance lifecycle defect + missing repeat test
Corroborates: Sol F5; independently strengthened with rendered-route analysis

Independent source reproduction:
- VisitStore.start() returns an existing complete session for the stable plan key.
- Course Practice links REVIEW to the stable `course:review:course` route.
- after new topics create newly eligible fresh review questions, the same route still returns the old completed REVIEW rather than building a fresh plan.
- Course Practice also labels completed game routes “Play again” but links to the same stable APPLY session key. SessionView calls start(), so “Play again” can land on the already-completed game/debrief rather than starting another play.
- SessionView’s explicit in-completion “Practise again” button calls restart() and is a separate path; that does not fix the normal Practice/Up Next/Play-again route semantics.

Minimum acceptance repair:
- separate completed history from a new session instance;
- unfinished instance resumes intentionally;
- a stable REVIEW route creates a fresh eligible instance when fresh questions exist;
- Play again actually starts a new APPLY instance while retaining prior completion history;
- audit READY and teacher SET repeat entry under the same rule.

Corroborates Sol F11. Course/topic routes for unadded General content recover to Discover, but /general/learn/... starts directly because session route validates only course context.

ST-P3-02 — AttemptReceipt is root-frozen only; nested response/confidence/support/feedback objects remain mutable.
Corroborates Sol F12. No current renderer mutation was found, so this is an adapter-hardening gap, not a current visible corruption.

ST-P3-03 — Settings section jump does not establish a focusable destination target.
Independent Stuart finding / source-level accessibility defect + missing test.

Evidence:
- Settings intercepts each jump link, prevents native anchor navigation, scrolls the section into view, then calls `.focus()` on its h2.
- Group renders that h2 without tabIndex or another focusability mechanism.
- the existing Settings browser tests exercise controls but do not test a Settings jump and destination focus.

Expected repair acceptance:
- keyboard activate a Settings section jump;
- viewport moves to the section and keyboard/programmatic focus lands on an explicit focusable destination heading/section target;
- subsequent Tab continues within that section rather than simply moving to the next jump link;
- no visible focus regression under normal and reduced motion.

ST-P3-04 — Stuck? → Show source overlay replacement has no durable focus-return chain.
Independent Stuart finding / source-level focus-isolation risk + missing nested-overlay test.

Evidence:
- Stuck? is a Modal; its Show source action replaces the single overlay state with Source rather than stacking/nesting or preserving an explicit return target.
- Modal captures `document.activeElement` locally on mount and restores only that element on unmount.
- replacing the Stuck modal removes the source-invoking button; the newly mounted Source modal has no durable reference to the original Stuck? page invoker.
- direct Task feedback → Show source focus return is tested, but Stuck? → Show source → Escape focus return is not.

Acceptance check:
- keyboard open Stuck? from an active question → Show source → close/Escape;
- return to a deterministic connected target (preferably the Stuck state/invoker or the page Stuck? button according to final interaction design), never body/lost focus;
- same result under reduced motion and after repeated overlay transitions.
