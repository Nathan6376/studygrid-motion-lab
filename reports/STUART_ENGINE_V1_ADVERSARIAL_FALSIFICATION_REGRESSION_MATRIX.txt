VERDICT
AMEND.

The current architecture is a viable specification target, not a blocked architecture. Keep the central epistemic separation:
OBSERVATION != EVIDENCE INTERPRETATION != LEARNER ESTIMATE != PEDAGOGICAL NEED/HYPOTHESIS != POLICY DECISION.

However, Draft 1 cannot yet pass this reusable matrix deterministically. The smallest Draft-2 repair package is:
1. split immutable response/presentation facts from append-only scoring/evaluation revisions;
2. define evidence sufficiency, channel comparability, family diversity and attribution per claim contract;
3. add mapping validity + retroactivity/quarantine semantics;
4. add semantic source-impact + derived-state freshness/stale barriers;
5. split administrative/policy sequence from cognitive prerequisite hypotheses;
6. define a complete policy branch order, tie rule, bounded repair/probe budgets and first-class no-action/blocked outputs;
7. represent learner override/offline declaration as bounded decision context, never competence evidence;
8. add issue→revalidate→deliver→respond/evaluate lifecycle, idempotency and concurrency rules;
9. define deletion-aware reconstruction with FULL/PARTIAL/UNAVAILABLE status and no hidden data duplication;
10. define instructor denominators, small-cohort/privacy release rules and content-quality alternatives;
11. bind UI labels to backend evidence strength so product language cannot overstate evidence;
12. keep accessibility/accommodation capability authorization independent from generic tutoring while recording construct-validity effects where needed.

The matrix below tests behaviour and invariants, not schema/table/service choices.

======================================================================
A. EPISTEMIC SEPARATION / NON-INFERENCE
======================================================================

S01 — PAGE VIEW IS NOT COMPETENCE
Input: learner opens a lesson, scrolls to bottom, answers nothing.
Permissible: exposure/completion observation; optional session progress.
Forbidden: demonstrated/learned/retained; readiness increase; instructor weakness/strength inference.
Invariant: exposure/completion never becomes mastery evidence by itself.

S02 — UI/INPUT FAILURE IS NOT LEARNER WEAKNESS
Input: answer control fails to submit; telemetry shows client error; no valid response committed.
Permissible: invalid/missing evidence; operational error; retry/recovery action.
Forbidden: incorrect-answer evidence; remediation; competence decrease.
Invariant: software/input failure remains separate from learner evidence.

S03 — POLICY OUTPUT CANNOT BECOME EVIDENCE
Input: policy recommends prerequisite review because estimate is sparse.
Permissible: decision/history record showing recommendation and reason.
Forbidden: feeding “review recommended” back as proof the prerequisite is weak.
Invariant: policy decisions never become learner evidence merely because they occurred.

S04 — MISCONCEPTION HYPOTHESIS CANNOT SELF-AUTHOR EVIDENCE
Input: two errors create hypothesis H; next task is selected because of H.
Permissible: H remains hypothesis with competing explanations and selection context.
Forbidden: treating H or task selection as independent supporting evidence for H.
Invariant: derived hypotheses are not observation facts.

S05 — SESSION COMPLETE IS NOT LEARNED
Input: learner finishes all assigned session tasks with mixed results.
Permissible: session/control completion; evidence remains claim/channel-specific.
Forbidden: “course/topic learned” solely from completion.
Invariant: navigation/control state cannot collapse into learner state.

S06 — NON-RESPONSE IS UNKNOWN, NOT FAILURE
Input: learner leaves before answering a task.
Permissible: no-response event; unknown/missing evidence; session recovery.
Forbidden: incompetence, laziness, disengagement or wrong-answer inference.
Invariant: missing-not-at-random data is not silently scored as low ability.

======================================================================
B. EVIDENCE SUFFICIENCY / CHANNELS / EXPOSURE
======================================================================

S07 — ONE CORRECT RECOGNITION ITEM
Input: one easy multiple-choice recognition item answered correctly.
Permissible: bounded correct observation in recognition channel; SPARSE/insufficient state.
Forbidden: durable competence, application competence, retention, transfer.
Invariant: one response cannot satisfy a stronger claim unless an explicit approved contract says so.

S08 — RECOGNITION VS APPLICATION DIVERGENCE
Input: recognition items strong; novel application task weak.
Permissible: separate channel profiles; divergence/conflict only if comparability rule declares it.
Forbidden: arbitrary average into one mastery score; stronger label than either channel warrants.
Invariant: channel-specific evidence is preserved when constructs/conditions differ.

S09 — ANSWER EXPOSURE THEN REPEAT
Input: answer shown after attempt 1; same item reappears in another tab/session and is correct.
Permissible: repeated/exposed performance; practice memory observation.
Forbidden: relabelling second result “unaided transfer” because hintCount=0 on second attempt.
Invariant: answer/support exposure lineage follows the relevant item/family/episode.

S10 — COACHED SUCCESS
Input: worked example or answer-bearing hint precedes correct solution.
Permissible: supported/coached success; evidence for supported performance if contract allows.
Forbidden: treating as equivalent to delayed unaided retrieval.
Invariant: support conditions travel with evidence and affect permissible inference.

S11 — FALSE TASK-FAMILY DIVERSITY
Input: five cosmetic variants share identical solution template but are labelled five families.
Permissible: repeated/correlated practice evidence; mapping/family review.
Forbidden: counting them as five independent transfer observations.
Invariant: family diversity reflects construct variation, not author-assigned IDs alone.

S12 — SPARSE MIXED EVIDENCE
Input: one correct, one incorrect, both valid but low coverage.
Permissible: OBSERVED_INSUFFICIENT/SPARSE; bounded descriptive history.
Forbidden: strong competence/weakness label from count alone.
Invariant: claim-specific sufficiency predicate controls strong claims.

S13 — INVALID ITEM
Input: item wording is later found ambiguous; many learners missed it.
Permissible: invalidate/quarantine interpretation; route item/content to review; preserve attempts.
Forbidden: learner remediation or competence decrease from invalid item.
Invariant: invalid evidence cannot become learner weakness.

S14 — UNKNOWN OFFLINE HELP
Input: learner completes task at home; system cannot know whether outside help was used.
Permissible: observed response under unknown-help condition; explicit limitation.
Forbidden: forensic certainty that result was unaided.
Invariant: absence of logged support is not proof of no external support.

S15 — TRANSFER CLAIM NEEDS TRANSFER EVIDENCE
Input: learner succeeds on repeated near-transfer templates only.
Permissible: performance on practiced family.
Forbidden: “can transfer to novel contexts” without approved novel/transfer evidence.
Invariant: transfer is a distinct inference contract, not a synonym for high correctness.

======================================================================
C. MULTI-CLAIM TASKS / SCORING / CONSTRUCTED RESPONSE
======================================================================

S16 — MULTI-CLAIM WRONG ANSWER WITHOUT ATTRIBUTION
Input: one scenario maps to claims A/B/C; total answer is wrong; rubric has no component isolation.
Permissible: joint/conjunctive evidence; diagnostic uncertainty.
Forbidden: lowering A, B and C independently as if each failure were isolated.
Invariant: per-claim negative evidence requires attributable scoring/observation.

S17 — PARTIAL RUBRIC ATTRIBUTION
Input: constructed response meets reasoning criterion A but fails unit/format criterion B.
Permissible: A positive, B negative if rubric/mapping explicitly isolates them.
Forbidden: copying total score to every mapped claim.
Invariant: evidence follows rubric components actually linked to claims.

S18 — CONSTRUCTED RESPONSE PENDING HUMAN SCORE
Input: response committed; no score yet; scorer service unavailable.
Permissible: response observation + PENDING/UNSCORED status; alternative valid action or wait.
Forbidden: treating pending as wrong or as zero competence.
Invariant: response existence and evaluation result are separate states.

S19 — LATE REGRADE
Input: scorer v1 gives 0.4; authorized regrade v2 gives 0.8.
Permissible: append-only score/evaluation revision; one effective current lineage; old decision replay under v1.
Forbidden: rewriting raw response, erasing v1, or counting both as independent evidence.
Invariant: immutable response + versioned evaluation revisions.

S20 — TWO SCORERS DISAGREE
Input: two valid scorers disagree on an essential criterion.
Permissible: scorer disagreement/REVIEW_REQUIRED; human/adjudication path; uncertainty.
Forbidden: arbitrary average presented as factual mastery.
Invariant: scorer disagreement is explicit, not hidden inside one scalar.

S21 — LATE CALLBACK AFTER MANUAL OVERRIDE
Input: human reviewer sets final score; old AI callback arrives later.
Permissible: precedence rule keeps authorized final evaluation; late callback preserved/rejected as stale.
Forbidden: late callback silently replacing reviewer decision.
Invariant: scoring lineage has explicit authority/precedence and idempotency.

D. REMAP / SOURCE / MODEL / POLICY REVISION AND FRESHNESS
======================================================================

S22 — ITEM REMAP A→B
Input: item originally mapped to A; mapping corrected to B after attempts.
Permissible: explicit retroactivity state: future-only, retroactive-safe, invalidate-old, or review-required; raw attempts unchanged.
Forbidden: counting one attempt for A and B simultaneously without approved interpretation; silently moving competence.
Invariant: mapping revision controls interpretation lineage, not observation history.

S23 — WRONG-BUT-CURRENT MAPPING CHALLENGED
Input: mapping is current/versioned but later flagged invalid.
Permissible: mapping UNDER_REVIEW/INVALID; affected interpretations stale/quarantined; diagnostic for claim.
Forbidden: ADVANCE or strong claim based on quarantined mapping.
Invariant: explicit mapping existence is insufficient; validity/approval state gates evidence authority.

S24 — COSMETIC SOURCE REVISION
Input: formatting/typo-only source revision; meaning unchanged.
Permissible: preserve comparable evidence; record source revision and impact classification.
Forbidden: global invalidation of tasks/estimates merely because version number changed.
Invariant: source impact is semantic/dependency-scoped, not version-number panic.

S25 — SEMANTIC SOURCE REVISION
Input: authoritative rule changes materially from v1 to v2.
Permissible: old performance remains historical-under-v1; affected interpretations/tasks/mappings identified; current state recomputed/quarantined as required.
Forbidden: treating v1 evidence automatically as current-v2 competence without comparability rule.
Invariant: versioned authority + selective impact cascade.

S26 — MODEL REVISION M1→M2
Input: same observations interpreted under new estimator/model config.
Permissible: new derived estimate; old decision remains reconstructable under M1.
Forbidden: overwriting historical decision explanation as if M2 was used then.
Invariant: derived models can change without rewriting history.

S27 — POLICY REVISION AFTER RECOMMENDATION ISSUE
Input: recommendation issued under practice; policy switches to protected before open/delivery.
Permissible: revalidate and suppress prohibited content; create new decision/recovery outcome.
Forbidden: delivering cached answer-bearing help because original decision was valid when issued.
Invariant: execution revalidates material policy/access before delivery.

S28 — DEADLINE CORRECTED AFTER CACHED URGENCY DECISION
Input: due date changes; cached action reason says “exam tomorrow.”
Permissible: stale reason/decision invalidated and recomputed from current trusted deadline.
Forbidden: delivering obsolete urgency rationale.
Invariant: decision-relevant context has freshness/version semantics.

S29 — ESTIMATE STALE AFTER NEW SCORE
Input: learner estimate computed before later valid score arrives.
Permissible: stale marker/recompute before material recommendation.
Forbidden: ranking on stale estimate while claiming current evidence.
Invariant: estimate carries evidence cutoff/watermark and dependency versions.

S30 — CANDIDATE GENERATOR REVISION
Input: generator v2 adds an eligible task omitted by v1.
Permissible: new current decision may differ; historical decision retains generator/pool revision.
Forbidden: claiming old candidate list was complete under v2.
Invariant: candidate-pool/generator identity is part of decision reconstruction.

E. PREREQUISITES / GRAPH FAILURE MODES
======================================================================

S31 — HARD PREREQUISITE UNKNOWN
Input: no evidence about prerequisite A; downstream B is otherwise available.
Permissible: bounded probe/introduction/review if authorized; UNKNOWN state.
Forbidden: treating unknown as failed or permanently blocking learner as incompetent.
Invariant: unknown != failed.

S32 — SOFT PREREQUISITE CYCLE A↔B
Input: soft/hypothesized edges create cycle.
Permissible: quarantine/review edges; continue with non-cyclic valid actions/probes.
Forbidden: infinite remediation loop or absolute block.
Invariant: inferred soft edges cannot deadlock the learner.

S33 — BROKEN HARD EDGE
Input: declared hard edge is later found wrong; learner has valid direct evidence for downstream competence.
Permissible: edge correction/review; preserve downstream evidence.
Forbidden: deleting/discounting downstream competence solely because old edge existed.
Invariant: graph correction does not rewrite observations or manufacture learner weakness.

S34 — POLICY SEQUENCE VS COGNITIVE PREREQUISITE
Input: course requires module A before B administratively, but learner already demonstrates B.
Permissible: enforce availability sequence as policy if authoritative; separately avoid saying learner is cognitively unable.
Forbidden: using administrative order as causal evidence of cognitive dependence.
Invariant: POLICY_SEQUENCE_REQUIRED is distinct from LEARNING_PREREQUISITE_HYPOTHESIS.

S35 — PREREQUISITE CORRELATION IS NOT CAUSAL BOTTLENECK
Input: A and B errors co-occur in cohort.
Permissible: descriptive association/hypothesis; targeted inspection/probe.
Forbidden: “A caused B weakness” without validated dependency evidence.
Invariant: causal prerequisite claims need more than correlated errors.

S37 — REPEATED OVERRIDES MUST NOT CREATE NAG LOOP
Input: learner rejects same recommendation repeatedly.
Permissible: bounded recommendation-history effect, alternative eligible action, optional reason.
Forbidden: same unsolicited recommendation regenerating indefinitely; learner penalty.
Invariant: anti-nag policy is separate from learner estimate.

S38 — PROTECTED ASSESSMENT SHIELD

Permissible: suppress unauthorized tutoring; preserve permitted assessment flow.
Forbidden: worked example/hint that violates assessment policy.

S39 — AUTHORIZED ACCOMMODATION DURING PROTECTED ASSESSMENT
Input: protected task; approved read-aloud/alternate input is authorized and construct-preserving.

Forbidden: blocking all support because “high stakes”; treating accommodation as incompetence.
Invariant: accessibility authorization is independent from tutoring prohibition.

S40 — ACCOMMODATION CHANGES CONSTRUCT INTERPRETATION
Input: read-aloud is authorized but task’s intended construct is reading decoding.
Permissible: allow access if authorized while marking comparability/construct interpretation according to contract.
Forbidden: treating evidence as equivalent without construct-validity rule; inferring disability.
Invariant: accommodation metadata affects validity only where necessary, not learner worth.

S41 — OFFLINE STUDY SELF-REPORT
Input: learner says “I already studied this elsewhere”; no validated external artifact.

Forbidden: direct demonstrated/mastery increase from self-report alone.
Invariant: self-report context is separate from validated evidence.

S42 — VALIDATED EXTERNAL INSTRUCTOR EVIDENCE
Input: authorized assessor records physical/procedural performance under a defined claim contract.
Permissible: external evidence channel with provenance/conditions.
Forbidden: treating an unauthenticated learner note as equivalent assessor evidence.
Invariant: external evidence authority is explicit.

S43 — GENERATIVE AI OUTAGE
Input: explanation generator unavailable; core package and fixed tasks remain.

Forbidden: inventing scores/content or blocking all core adaptation if AI is optional.
Invariant: AI is not hidden authority or single point of core truth.

======================================================================
M. EVIDENCE REQUIRED LATER TO CLAIM SOFTWARE CONFORMANCE
======================================================================

A future software PASS must be tied to exact implemented bytes/build + exact seeded fixtures. Minimum evidence:
1. exact build/revision/hash and policy/catalog/model configuration identities;
2. versioned fixture package containing source/task/claim/mapping/scorer/policy states used by each scenario;
3. authoritative response/score/decision IDs proving idempotency and effective lineage;
4. before/after state assertions showing raw observations did not mutate across remap/regrade/model changes;
5. decision records with evidence cutoff/watermark, candidate generator/pool revision, branch/tie path, selected/excluded IDs/reasons and execution/revalidation status;
6. controlled concurrency traces for two-tab, retry and late-callback fixtures;
7. policy/access traces proving protected-assessment denial and accommodation authorization at delivery time;
8. deletion/retention test proving no prohibited duplicate raw data remains in decision traces/caches and reconstruction status degrades truthfully;
9. instructor aggregate fixtures showing exact denominators, suppression/release decision and item-quality alternative;
10. UI snapshot/semantic assertions proving sparse/conflicting/stale/model-unsupported states cannot render stronger evidence labels;
11. accessibility checks for supported interaction families, including non-drag equivalent ordering controls where applicable;
12. negative tests for unsupported interaction/scorer types: system must refuse/pending/abstain, never silently substitute MCQ or mark wrong;
13. replay/reconstruction test under pinned historical versions and a separate current-state recomputation test; these must not be conflated;
14. test evidence must distinguish specification conformance from empirical validity: a green fixture only proves the programmed rule executed as specified.

Software conformance DOES NOT establish:
- that evidence contracts are psychometrically valid;
- that the policy improves learning;
- that retention estimates are calibrated;
- fairness across populations;
- causal effectiveness of remediation or recommendation order;
- institutional-scale reliability.

Those require separate predeclared empirical evidence such as delayed/transfer outcomes, appropriate comparators, scorer/rater validity evidence, instructor/learner studies, accessibility/fairness evaluation and a defined population. Do not convert synthetic regression PASS counts into learning-efficacy claims.
